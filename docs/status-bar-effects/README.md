# 상태 표시줄 이펙트 애니메이션 — 기획 문서 모음

안드로이드(폰·태블릿) 상태 표시줄과 macOS 메뉴 막대 위에서 돌아가는 "가로로 긴 미니 어항" 애니메이션의 2차 기획안입니다.
로컬 앱 폴더로 이 디렉터리를 통째로 복사해서 작업용 명세로 쓰는 것을 전제로 작성했습니다.

## 왜 바꾸나 — 1차 버전의 한계

| 1차 버전 (말 달리기, 검도 머리치기) | 문제 |
| --- | --- |
| 캐릭터 1명이 같은 동작을 반복 | 몇 번 보면 패턴이 다 읽힘 → 단조로움 |
| 빈 배경 | 가로 공간 대부분이 비어 있음 |
| 랜덤성 없음 | 어항의 물고기처럼 "다음엔 뭐 하지?" 하는 기대감이 없음 |
| 세로 정보(캐릭터 디테일)에 의존 | 세로가 20px 남짓이라 디테일이 거의 안 보임 |

## 핵심 방향 — "캐릭터는 작게, 이펙트는 길게"

1. **가로 전체를 쓰는 이펙트가 주인공이다.** 번개 줄기, 화염 파도, 달려나가는 정령 동물, 화면을 가르는 일섬처럼 왼쪽 끝에서 오른쪽 끝까지 뻗는 움직임이 승부처.
2. **캐릭터는 "발사대"이다.** 세로 높이 안에서 실루엣으로 알아볼 정도만 그리면 된다. 디테일은 탭/클릭해서 펼치는 상세 화면에서 보여준다.
3. **배경이 계속 살아 있어야 한다.** 풀, 꽃잎, 구름, 불씨처럼 쉬는 동안에도 조금씩 움직이는 레이어를 깐다 (어항의 물풀·기포 역할).
4. **매번 조금씩 다르게.** 시드 기반 랜덤으로 변형(variant), 타이밍, 위치, 개수를 바꾼다. 같은 변형이 연달아 나오지 않게 한다.
5. **긴장 → 폭발 → 여운 리듬.** 대부분의 시간은 조용한 대기(Idle)이고, 가끔 짧고 강한 이펙트가 터진다. 계속 번쩍이면 피곤하고 배터리도 먹는다.

## 기존 장면에 바로 적용할 수 있는 개선 (덤)

새 장면을 만들기 전에 이 공통 부품만 붙여도 1차 장면이 꽤 살아납니다.

- **말 달리기**
  - 바닥 2~3px에 풀 타일을 깔고 시차(parallax) 스크롤: 먼 언덕 0.2배, 풀 1.0배, 앞쪽 풀 끝 1.4배.
  - 발굽마다 흙먼지 파티클 2~3개.
  - 가끔(15%) 울타리 점프, 토끼가 튀어 도망감, 새 떼가 날아오름 같은 랜덤 이벤트.
  - 바람 줄기(가로로 긴 1px 흰 선)가 말을 앞질러 지나감 → 속도감.
- **검도 머리치기**
  - 죽도 끝 궤적에 호(arc) 잔상 3프레임.
  - 타격 순간 0.08초 정지(히트스톱) 후 충격파 링.
  - 기합 순간에 가로로 퍼지는 바람 압력선. 발 구름(후미코미) 때 바닥 먼지.
  - 상대가 가끔 바뀜(죽도 든 그림자, 짚단).

## 작업 순서 제안

1. `ENGINE.md`의 공통 부품(파티클, 상태 머신, 시드 랜덤, 히트스톱)을 먼저 구현한다. 세 장면 모두 이걸 재사용한다.
2. 장면 3(벚꽃 일섬)부터 만든다. 스프라이트는 가장 적게 들고 효과는 가장 크게 체감된다.
3. 장면 1(마법사) → 장면 2(드루이드) 순서로 만든다. 드루이드는 동물 스프라이트가 많아서 가장 손이 많이 간다.
4. 장면마다 각 문서 끝에 있는 **완료 기준 체크리스트**로 검수한다.

> 저작권 메모: 장면 2·3은 특정 작품의 *연출 장르*(소환술, 발도 일섬)에서 영감을 받았을 뿐, 캐릭터·의상 문양·기술 이름은 모두 오리지널로 디자인한다. 특정 작품 캐릭터의 머리색·하오리 무늬·기술명을 그대로 쓰지 않는다.
